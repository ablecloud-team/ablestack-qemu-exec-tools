# #1034 / #962 최소 잔여 구현 및 검증 (2026-09-11)

## 결과와 범위
#1034의 손상된 과거 완료 정보에서 새 체크포인트를 게시하고 UI 작업을 완료하는 경로를 구현했다. #962는 기존 삭제 메뉴와 같은 확인창의 강제 옵션을 재사용하여 최소 탈출 경로를 검증했다. 전체 orphan 조회/자동 정리 UI는 이번 범위가 아니며 #962에 P2 잔여로 남긴다.

기준 HEAD: Cloud `60b9bc42fa`, qemu `4493037`. 두 저장소의 안전 브랜치는 `codex/fix-1034-962-ui-recovery`이다. 기존 통합 개선을 보존한다. 생산 코드 변경은 Cloud의 KVM status wrapper, site broker, DR projection 세 클래스이며 qemu는 설계·검증 문서만 변경한다.

## 구현
- Agent는 과거 completed evidence CONFLICT/INCOMPLETE를 오류로 유지한다. 유효한 별도 pending candidate만 publication 전용 오류 envelope에 보존한다. Plan identity, CLI 종료, 타입, 양수 sequence, producer, disk set을 확인한다.
- 레거시 원격 소스의 빈 active_side는 READY/SYNCING/PAUSED에서만 호환한다. Cloud의 실제 Plan SOURCE 조건과 lifecycle 권한 검증을 유지한다. TARGET 및 전환 terminal은 제외한다.
- Broker는 실패를 성공으로 바꾸지 않고 전달한다. pending이 없더라도 retired worker의 오래된 READY를 되살리지 않는다. healthy live worker 및 lifecycle terminal 우선권을 유지한다.
- Cloud의 누락된 CONFLICT boundary 분류를 추가했다. 새 candidate는 기존 target publish 계약을 통과하고 정확히 같은 COMMITTED proof와 manifestSha256이 확인돼야 ACK한다. 손상 snapshot은 마지막 정상 투영을 덮어쓰지 않는다.
